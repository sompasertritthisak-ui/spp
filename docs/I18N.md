# Languages — English and Lao (ລາວ)

SPP is based in Laos, so the website's interface speaks both languages. The
visitor switches with the **EN | ລາວ** control in the header, the mobile menu,
the footer and the sign-in screens. The choice is remembered on that device.

## How it works

| Piece | Where |
|---|---|
| Dictionaries | `src/lib/i18n/en.ts` (source) and `src/lib/i18n/lo.ts`. Flat dotted keys, `{name}` placeholders. `lo` is typed `Record<Key, string>`, so a missing Lao string is a **type error**. |
| Pure core | `src/lib/i18n/core.ts` — `translate()`, `interpolate()`, `translateLiteral()`; no React, unit-tested in `tests/i18n.test.ts`. |
| Client layer | `src/lib/i18n/index.tsx` — `LangProvider`, `useT()`, `useLang()`, `useLiteral()`, and the `<T k="…" />` / `<Tx text="…" />` components that server components can render. |
| Switch | `src/components/site/LangToggle.tsx`. |
| Mounted in | `src/components/site/Providers.tsx` (wraps the whole app). |

The site is a **static export**, so the HTML on disk is always English (good
for search engines and for the first paint). After hydration the saved language
(`localStorage["spp.lang"]`) is applied through `useSyncExternalStore`, which
keeps the first client render identical to the markup — no hydration mismatch.
The provider then sets `<html lang>` and the type stacks.

**Type.** Geist, Bricolage Grotesque and JetBrains Mono have no Lao glyphs.
Noto Sans Lao (self-hosted by the root layout as `--font-notolao`) is slotted
in *after* each Latin face, so Latin text keeps the brand typefaces and Lao text
gets a real Lao face instead of whatever the device falls back to. Translated
headings and labels get extra line-height: Lao stacks vowel and tone marks above
and below the line.

## Adding or changing a string

1. Add the key to `en.ts`, then to `lo.ts` (the type check fails until you do).
2. Client component: `const t = useT(); t("area.key", { n: 3 })`.
   Server component: `<T k="area.key" />`.
3. A label handed to shared chrome as a plain string (`CtaBand`, `PageHero`,
   `SectionHead`) is translated when it is listed in `LITERALS` in `core.ts`.
4. Keep brand and product names in Latin script: SPP, SPP Studio, My SPP, WhatsApp.
5. `npx vitest run tests/i18n.test.ts` — checks key parity, matching
   placeholders, and that Lao entries are actually written in Lao.

## What is translated

Navigation and calls to action, footer, the Get-in-touch band, the closing CTA
band, page-hero eyebrows and buttons, the quote builder (labels, hints, buttons,
validation, summary, success screen), estimate widget, project builder, campaign
builder, bundles list, solutions hub labels, consultation and contact forms, the
offline hand-off, sign-in / register / reset screens, and My SPP (navigation,
page headings, empty states, My Designs in full).

## Whole-page Lao (added 2026-10-21)

The dictionary in `en.ts` / `lo.ts` covers the chrome. Everything else a visitor reads — product copy, billboard pages, articles, legal pages, the Studio's panels and buttons — is translated by a second layer:

- **Segments.** The inline content of each block element (paragraph, heading, list item, button) is one segment, serialised as a key such as `Design your own <1>T-shirt</1> online in sizes XS to {#}XL.` — `<n>` marks the n-th inline element, `{#}` a number. `src/lib/i18n/segments.ts` is the pure model (keys, tokens, validation); `src/lib/i18n/dom-translator.ts` swaps a page into Lao in place and back again, reusing text nodes and moving (never cloning) inline elements, with a MutationObserver for whatever React re-renders. Wrappers made only of spans and icons fall back to their parts. SVG, code and form controls are never touched, so a customer's own design text in the Studio stays as typed.
- **Dictionary.** `src/content/lao/segments.json` (`segments`, `attrs` for placeholder / aria-label / title / alt). Loaded only when the visitor chooses Lao (`src/components/site/LaoContent.tsx`, mounted in `Providers`). ~2,800 segments and ~350 attributes, written by Claude and validated: same tags, same number slots, Lao script present. A key with no entry renders in English.
- **Keeping it current.** After a build with `node scripts/serve-out.mjs 4173` running: `npx tsx scripts/i18n-extract.ts` crawls every exported page with the real collector plus the client-side JSX, writes `scripts/data/i18n-segments.json`, and splits untranslated keys into `scripts/data/pending/<page>-NN.json`. Translate into `scripts/data/lao/<same name>.txt` as `N<TAB>Lao` lines (`python3 scripts/data/show.py <name>` prints the numbered keys), then `npx tsx scripts/i18n-merge.ts` validates and merges; every processed batch retires to `lao/done/`. Keys that are codes, brand names or colour values are left untranslated on purpose.
- **Tests.** `tests/lao-content.test.ts` (model + every shipped entry validates); e2e "lao:" toggles a product page and the Studio.
- **Coverage audit.** `npm run i18n:audit` (with the export served on 4173) opens every page in Lao, drives the Studio panels and dialogs, the quote builder, form validation, the billboard visualiser and the map, and writes every piece of visible English left to `scripts/data/i18n-leftovers.json`. Run it after translating; the target is an empty list apart from codes and brand names.
- **Dynamic messages.** Studio preflight messages are dictionary keys (`pf.*` in `en.ts`/`lo.ts`) with values, rendered in the visitor's language by the panel; the English rendering is what gets stored. Browser-tab titles translate too (the " — SPP" suffix is kept). Month names are expanded to all twelve in the dictionary. Jarvis is told the visitor's language and answers in Lao.
- **Not covered.** Meta descriptions (not visible), the value typed into inputs, and content staff add later in the Command Center until its segments are extracted and translated with the steps above.
